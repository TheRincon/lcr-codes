LC Code display

Encodes on this device and draws the symbol at exact device pixels. Point the scanner page at it.

Mandatory on screen as of D14: the ring now carries the position sequence, so turning it off produces a symbol that is missing something a decoder is entitled to. Left togglable because what the border is worth under real glare has never been measured, and that is an A/B the capture sweep can run.

Compare against QR

Same payload, same module pitch, drawn by the same code. Generated by the qrcodegen crate and read back by an independent decoder in the test suite, so this is a measurement rather than a claim.

Impairments

Applied to the display, so the phone sees them through real optics. Carried into full screen.

For a reliable scan (§13.1): turn the laptop's brightness to maximum, turn off Night Shift / True Tone / any "vivid" colour mode, and leave the symbol still. Keep at least 8 pixels per module — the default 12 is inside the range the spec prefers. Hold the phone slightly off-axis so its own reflection lands away from the symbol (§13.2).

On the tilt sliders: tilting here is not the same as tilting the phone. A CSS transform resamples the symbol before it reaches the screen, so the browser's filter sits in the path — the same class of artefact that made this project's synthetic tilt measurements wrong until the harness was fixed. Physically moving the phone leaves the pixels intact and warps only the optical path, which is the honest test. Use the sliders to sweep quickly and find roughly where things break, then confirm the interesting cases by moving the phone. Glare and shadow carry no such caveat — they are composited over the symbol, not resampled.
